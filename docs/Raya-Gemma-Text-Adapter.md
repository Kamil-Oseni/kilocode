# Gemma text adapter handoff

The production retrieval module now provides an opt-in `Gemma` adapter. The existing Qwen classes and default worker selection remain unchanged. This is source support for the requested migration; it does not claim that the installed service has switched models or enabled capture.

The caller must authenticate and admit the checkpoint manifest and every file before constructing the adapter. Its consistency checks require `google/embeddinggemma-2`, revision `914f7f89142e33e77833254d9c9b90c3cef7303b`, and `downloaded_verified`. Constructor checks alone do not authorize a checkpoint.

The adapter loads local files on CPU with float32 and disables the vision/audio towers. It uses the checkpoint's Document and SearchQuery prompts, limits each input including its prompt to 512 tokens, and returns finite normalized 768-dimensional vectors. Documents must be split before encoding; overlong input is refused rather than silently truncated. Requests contain at most 32 texts and inference batches contain two texts.

The implementation was exercised with the pinned checkpoint, sentence-transformers 6.1, Transformers 5.19, and CPU PyTorch 2.14. These are evaluation dependencies, not yet an admitted production dependency closure.

- Actual adapter peak RAM: 1.82 GiB; minimum system free RAM: 12.42 GiB. The finite child exited successfully and was joined with no owned process remaining.
- Managed memory owner/notes: 17 tests passed, 123 assertions.
- Portable source/catalog: three tests passed.
- Exact supervisor release admission: three tests passed using its pinned Python interpreter.
- Extension host and webview type checks passed; scoped catalog lint passed.

The first private adapter probe failed before model loading because its source comparison used Windows' default text encoding. The corrected UTF-8 probe passed. The first portable run encountered generated bytecode in its exact source inventory; the bytecode was preserved outside the source directory and the rerun passed. The first supervisor test run used an unselected system Python and was correctly refused; the pinned-interpreter rerun passed. These are preserved failures, not production success claims.

## Remaining installation work

The service owner still needs to admit Gemma and its dependencies through bootstrap, select this adapter in the worker, create a separate 768-dimensional index namespace and rebuild it, and deploy bounded worker reuse. Automatic capture of Raya conversations and actions must then be installed and verified. Ambient microphone/screen capture remains outside the requested scope.

Retrieval source hashes were updated through bootstrap, owner, supervisor and the extension catalog so this source change can be admitted coherently. A release note should accompany the user-visible migration when it is actually selected and installed.
