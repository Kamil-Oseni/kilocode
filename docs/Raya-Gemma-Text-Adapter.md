# Gemma text adapter handoff

The production retrieval module now provides a `Gemma` adapter and explicit `embeddinggemma-2` requests through the retrieval service. Requests without a model retain Qwen compatibility for rollback. This is source support for the requested migration; it does not claim that the installed service has switched models or enabled capture.

The caller must authenticate and admit the checkpoint manifest and every file before constructing the adapter. Its consistency checks require `google/embeddinggemma-2`, revision `914f7f89142e33e77833254d9c9b90c3cef7303b`, and `downloaded_verified`. Constructor checks alone do not authorize a checkpoint.

The adapter loads local files on CPU with float32 and disables the vision/audio towers. It uses the checkpoint's Document and SearchQuery prompts, limits each input including its prompt to 512 tokens, and returns finite normalized 768-dimensional vectors. Documents must be split before encoding; overlong input is refused rather than silently truncated. Requests contain at most 32 texts and inference batches contain two texts.

The implementation was exercised with the pinned checkpoint, sentence-transformers 6.1, Transformers 5.19, and CPU PyTorch 2.14. These are evaluation dependencies, not yet an admitted production dependency closure.

The bootstrap now admits the exact Gemma catalog bytes and checks all fifteen checkpoint files before selected Gemma inference. It refuses unsafe names, unexpected inventory, links/reparse points, size/hash changes and observed file-generation changes. Windows path and descriptor ctime are each checked within their own API channel, matching the existing admission verifier. Requests return their selected model identity; the result validator accepts 768 dimensions for Gemma and 1024 for Qwen and rejects cross-model results. Reranking remains Qwen.

This adds the Gemma catalog to the exact service release. Deployment must provide the matching catalog and admitted dependency closure together; it must not copy these sources into an old running capsule. The live catalog SHA is pinned, so changing catalog metadata also requires an explicitly reviewed pin update.

The final actual worker/validator regression passed three synthetic query matches and foreign-model refusal. It ran two finite embedding requests, peaked at 3.04 GiB RAM, retained at least 7.37 GiB free RAM, and exited/joined with no child remaining. Four additional model-free tests verify real checkpoint admission, malformed manifest/hash refusal, selected-model dimensions, revision checks and invalid vectors. These checks do not start the installed HTTP service or prove reindexing or worker reuse. Exact worker evidence is archived alongside the adapter probe.

The first private adapter probe failed before model loading because its source comparison used Windows' default text encoding. The corrected UTF-8 probe passed. The first supervisor test run used an unselected system Python and was correctly refused; the pinned-interpreter rerun passed. These are preserved failures, not production success claims.
