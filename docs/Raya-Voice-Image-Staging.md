# Voice image staging

The protected OpenAI voice binding can retain up to eight immutable image attachments, each at most 256 KiB decoded. JPEG, PNG and WebP are accepted after canonical base64 and matching format-signature checks. These checks are not a full image decoder or a claim that every image will be accepted by a downstream provider.

`POST /kilocode/voice/openai/session/:id/images` requires the binding capability header, current generation, canonical workspace and active server owner. The payload is `{ generation, id, mime, data }`; `data` is base64 without a data-URL prefix. The response exposes only `{ id, mime, bytes, sha256 }`. Repeating the same ID and bytes is idempotent; changing that ID's retained bytes is refused. Closing/expiry or server-owner replacement prevents new uploads. Legacy bindings without an image collection behave as empty collections.

Uploading does not create a user turn or admit work. A later `raya_work` call may explicitly select at most four distinct attachment IDs in `arguments.images`. Only this binding's images are eligible. The service checks their retained bytes and receipts before admission and again before dispatch. The existing parent SessionPrompt receives the selected images as file data-URL parts beside the request; its permission and goal path remains authoritative. Call receipts retain selected image identities, and duplicate call IDs compare ordered attachment selections as well as the original request fields.

The receipt is an observation of staged bytes, not authorization to execute work, a provider completion receipt, or proof of unmodified external storage. Source signatures are checked again when images are consumed; malformed retained metadata and changed bytes are refused. Existing admitted work remains distinct from voice closure, as before. Image staging does not start screen capture or camera access, install anything, or create a second Raya session.

Actual Storage and shipped HTTP tests passed: 12 tests and 113 assertions, native exit 0 (`.tmp/voice-images-tests.log`). They cover bounded staging, immutable retries, format rejection, cross-binding IDs, owner/generation/capability/directory fences, no upload-triggered work, selected parent file parts and receipt consistency. CLI and generated SDK typechecks, SDK generation and scoped lint also exited 0; lint reported no warnings.

The static HTTP scenario registry check includes the new protected image route and exited 0 with 328 passing scenarios, no failures and 47 existing routes without scenarios (`.tmp/voice-images-coverage-final.log`). This is not complete HTTP coverage. Its first attempt could not create the default global directory under the sandbox; the recorded successful run used a fresh workspace-local test directory. These checks do not establish live OpenAI account delivery or device capture quality.
