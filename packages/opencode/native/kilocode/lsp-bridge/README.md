# Fixed Windows LSP bridge draft

This source has not been compiled or executed. It is not connected to the Lua launcher. The retained descendant-held-pipe regression remains failed. Do not mark the LSP writer complete or release its original lifetime based on the previous Bun stream observations.

The fixed build uses a self-contained `net8.0-windows` / `win-x64` multi-file publish. `PublishSingleFile` is false: no runtime compiler, package download, runtime extraction directory or user-installed .NET runtime is required by the proposed shipped closure. The complete published directory must be inventoried and copied as one verified package component, including the apphost, managed assemblies, native runtime libraries and symbols. Root must review and pin the selected SDK/runtime build inputs before compilation; this project does not make an SDK availability or supply-chain claim.

The parent must reserve its actual LSP admission before creating a fresh protected control directory. It verifies the complete installed bridge payload, canonical ordinary ancestors and the exact owner/System/Administrators DACL before launch. It launches the apphost directly with exactly `--control <fresh-directory>` and three private stdio pipes. The control directory, installed runtime closure, Lua image and namespaces remain bound until original bridge retirement and cleanup. Never accept executable/env/control paths from renderer or model input. The bridge's token/hash metadata is a host-owned correlation record, not independently authenticated native authority.

The first four stdin bytes are an unsigned little-endian startup length (1–65536), followed by exactly that many strict UTF-8 JSON bytes. The exact field set is `{version:1,token,target,sha256,cwd,args,env}`. Token is 32 hexadecimal characters; target digest is 64 hexadecimal characters. Arguments/environment are bounded, duplicate keys are refused, and local canonical absolute paths are required. No buffered text reader is used: the next stdin byte is the first raw LSP byte. Subsequent stdout contains only original LSP output. Separate fresh `launch.json` and `result.json` records are bounded to 16 KiB and opened with CreateNew. Original child PID/birth/image is recorded from its retained process handle; full job member identity observation is explicitly false.

Before child creation, the keeper owns its unnamed Job, pipes, exact thread callbacks and original native thread handles. The child is created suspended with creation-time JOB_LIST and exactly three inherited handles; no breakaway or kill-on-job-close option is set. All pumps are installed before creation. Every post-create failure runs the same keeper: ordinary resume if necessary, retained root wait, terminal input-only cancellation and exact thread join, original stdout/stderr native EOF and Job active count zero. Output forwarding failure is sticky and does not stop native draining. Cancellation success or ERROR_NOT_FOUND never substitutes for input join. Repeated terminal input cancellation covers a read racing the first cancellation without canceling either output reader.

The keeper deliberately has no retirement timeout or process termination path. The parent may impose a finite observation deadline, but must retain the exact original child/bridge handles, leases and pending cleanup after expiry. Original join/query/resume uncertainty retains the bridge instead of reporting closure. Broken parent pipes or a lost result file do not authorize replacing an unsettled owner. Result publication occurs while control-directory ancestry is still held. The final held bridge exit also joins handle release; the result record alone does not prove that final release.

Still required before integration: compiler/type checks, actual creation attributes in the Windows host's enclosing Job, exact inherited handle behavior, dedicated managed-to-native thread callbacks under the selected runtime, descendant-held-pipe regression, cancellation/read/write gap tests, target/parent failure tests, and complete payload/protection/ordinary-close joins. The test interpreter remains a disposable fixture rather than third-party Lua release acceptance. Declared archive bounds are not an OS disk quota. Linux/macOS family retirement and unrelated language-server installers/caches remain outside this finite stage.
