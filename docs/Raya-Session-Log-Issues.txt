EXECUTIVE SUMMARY
=================

The Etymon work exposed one confirmed application bug and several independent Raya/runtime failures that could look like application bugs:

1. Etymon's Continue/Back hang was a real React effect loop in LessonReader. This was diagnosed and fixed during the session.
2. Raya's browser host repeatedly wedged or timed out, preventing visual verification even when Etymon itself was responding.
3. The Next.js dev server repeatedly became stale, orphaned, stopped, or accepted connections without completing requests.
4. A provider/tool-schema incompatibility caused 18 French Study assistant failures and triggered many failed replacement subagents while trying to fix Vercel.
5. Session context grew beyond model limits despite pruning, causing 632 large-payload warnings and two explicit token-limit failures.
6. A response/event schema mismatch generated 164,892 runtime-wide warnings for a missing metadata.variant field, making the logs extremely noisy.
7. Vercel was configured inconsistently for a nested Next.js app, leading it to expect a public output directory instead of treating the app as Next.js.


ETYMON APPLICATION AND PROJECT ISSUES
=====================================

ISSUE E-01 - Lesson Continue/Back buttons appeared to hang
Severity: Critical for the affected lesson flow
Status: Fixed in the Etymon session; old open tabs still needed a reload
Evidence: User report on 2026-09-06; dedicated diagnosis session; pre-fix Playwright click timed out; last_opened_at rewrote repeatedly while idle.
Cause: LessonReader placed the whole identity API object in React effect dependency arrays. markLessonOpened changed the guest snapshot, IdentityProvider rebuilt the API object, the dependency changed, and the effect ran again indefinitely. The loop repeatedly wrote localStorage, recalculated progression, and rerendered the page, starving the main thread. A mount-time write also raced and overwrote the saved resume pointer.
Resolution recorded in the session: call the identity API through a ref and depend only on stable primitives such as ready, lesson.id, and sectionId. Verification reported zero idle writes, one write per section change, working Back/Continue controls, restored resume behavior, and a clean TypeScript check.

ISSUE E-02 - Stale Etymon tabs could keep the fixed render loop alive
Severity: High until tabs were reloaded
Status: Operational cleanup required after E-01
Evidence: The diagnosis observed a second lesson pointer still changing from another open tab after the source fix.
Cause: Hot reload updated the server code but an already-open browser tab continued executing the old client bundle and its infinite effect loop.
Remedy: Reload or close all old localhost:3000 tabs after deploying the fix.

ISSUE E-03 - The Etymon development server repeatedly stopped or became orphaned
Severity: High for development and review
Status: Recurring environmental problem
Evidence: The user reported that localhost:3000 stopped; the restart session found an untracked stale Next.js process tree holding port 3000. The user had to request a restart repeatedly.
Cause: Earlier server starts were tied to a session or left as untracked child processes. Their lifetime and ownership were not durable across agent/session boundaries.
Remedy: Start the server under one durable process owner, persist its PID/command, verify port ownership, and expose an authoritative restart/stop operation.

ISSUE E-04 - A later dev server accepted connections but never completed requests
Severity: High
Status: Recovered by restart; underlying recurrence risk remains
Evidence: On 2026-09-12, both browser and independent HTTP requests stalled while PID 17224 still accepted connections and emitted no new log lines.
Cause: The Next.js development process was alive at the socket level but internally hung. The logs do not prove whether Turbopack, application work, or resource pressure was the immediate blocker.
Remedy: Add a health check that tests a completed HTTP response, not only an open port, and automatically distinguish "listening" from "healthy."

ISSUE E-05 - Vercel treated the nested Next.js app as a static/Other project
Severity: High for deployment
Status: Repository-side diagnosis made; dashboard state was never verified
Evidence: Repeated Vercel error: No Output Directory named "public" found after the Build completed. Local Next.js production builds passed and generated 19 routes.
Cause: The app lives in etymon-web, but repo-root and app-root configuration were mixed. An earlier root vercel.json used framework:null, which disables framework detection. Moving a minimal vercel.json into etymon-web did not set Vercel's dashboard-only Root Directory. The public-directory error is consistent with Vercel using an Other/static preset or retaining public as its Output Directory instead of using the Next.js preset.
Remedy: Set Vercel Root Directory to etymon-web, Framework Preset to Next.js, clear any Output Directory override, and redeploy. Do not set outputDirectory to public or .next as a workaround.
Confidence: High, but the exact dashboard setting could not be inspected from the session.

ISSUE E-06 - The configured lint command is invalid for Next.js 16

Cause: Next.js 16 removed the next lint command, so "next lint" is interpreted as a project-directory invocation.

ISSUE E-07 - MicroCheck is effectively unreachable with the seeded content

RAYA BROWSER, PROCESS, AND TOOLING ISSUES

ISSUE R-01 - Browser host repeatedly timed out or became wedged
Severity: Critical for visual/frontend work
Status: Recurring
Evidence in French Study sessions: 13 browser_navigate host timeouts, 7 browser_evaluate host timeouts, 4 browser_tabs host timeouts, 2 browser_snapshot host timeouts, plus screenshot, click, navigation, and snapshot timeouts. The host wedged after a heavy 17-route screenshot/evaluation sweep and later recovered.
Cause: Long-running or queued browser actions left the tab plane unresponsive. Failed clicks could trigger manual-takeover state, after which unrelated browser calls also timed out. Heavy screenshot/evaluation workloads appear to increase the likelihood.
Remedy: Enforce per-tab action cancellation, bounded queues, host health probes, automatic tab replacement after repeated timeouts, and a supported reset action that preserves a clear receipt.

MODEL, PROVIDER, AND SESSION-CONTRACT ISSUES
============================================

ISSUE M-01 - Response/event schema rejected missing metadata.variant
Severity: High due volume and diagnostic impact
Status: Unresolved in retained logs
Evidence: 164,892 runtime-wide warnings; 3,233 during the main Etymon dates. Every sampled warning says: Expected JSON value, got undefined at [0]["metadata"]["variant"].
Cause: A producer emits metadata.variant as undefined while the receiving schema requires a JSON value. The event continues often enough that work proceeds, but every occurrence creates a warning.
Impact: Massive log noise, wasted I/O/storage, and reduced visibility of real failures.
Remedy: Omit optional undefined fields before serialization or make variant explicitly optional/nullable in the shared contract. Add a regression test at the producer/consumer boundary.

ISSUE M-02 - Provider rejected task tool schemas because parameters.type was missing
Severity: Critical for delegation
Status: Unresolved for the affected provider path
Evidence: 18 French Study assistant API errors, 19 runtime process errors, and 19 stream errors report: tools.function.parameters.type is required and must be "object". Repeated attempts spawned numerous short-lived Vercel-fix children that failed immediately.
Cause: The OpenAI-compatible request sent at least one function schema without a top-level parameters.type="object", and the Moonshot/Kimi endpoint enforced that requirement.
Remedy: Normalize every tool schema before provider dispatch, even when a tool has no arguments; add provider-contract tests and stop retrying a deterministic HTTP 400 with newly spawned children.

ISSUE M-03 - Deterministic subagent failures caused a retry/spawn storm
Severity: High
Status: Unresolved behavior
Evidence: The Vercel issue produced many Coder children with numbered duplicate titles. They failed with the same non-retryable schema error. Task calls also returned resumable child IDs, but replacement children continued to be created.
Cause: The orchestrator treated a provider-level deterministic schema rejection as if a fresh child might succeed.
Remedy: Classify non-retryable provider 400s, resume only when recovery is plausible, cap equivalent child retries, and escalate the shared provider/tool contract after the first repeated failure.

ISSUE M-04 - Session payload pruning did not keep context within limits
Severity: Critical for long sessions
Status: Unresolved in logs
Evidence: 632 runtime warnings say "payload still large after pruning," with sampled payloads around 1.26-1.35 MB. Two requests exceeded the 262,144-token model limit, requesting 519,485 and 398,574 tokens.
Cause: Long-lived sessions retained large tool outputs, attached documents, screenshots/evidence, and repeated continuation material. The pruning/compaction step did not reduce the final provider payload enough.
Remedy: Apply hard post-pruning token checks, summarize or externalize large tool outputs, avoid reinjecting full documents, and force compaction before provider dispatch rather than after a rejected request.

ISSUE M-05 - Invalid ModelMessage history reached the provider adapter
Severity: High
Status: Two runtime process errors; one in the Etymon overhaul
Evidence: "Invalid prompt: The messages do not match the ModelMessage[] schema."
Cause: Stored or reconstructed message history contained a shape/order not accepted by the AI SDK. The logs do not expose the exact invalid item safely enough to isolate it further.
Remedy: Validate and repair history before dispatch; log a redacted path to the invalid message/part instead of only the aggregate error.

ISSUE M-06 - Provider moderation rejected one redesign request

ISSUE M-07 - Provider transport failures interrupted work

The following were present but should not be counted as independent product defects without more evidence:

RECOMMENDED FIX ORDER
=====================

1. M-02: normalize tool schemas before provider dispatch. This blocked delegation and caused the largest visible retry storm.
2. M-04 and M-09: enforce hard context limits and concurrency/rate controls.
3. M-01: stop metadata.variant warning spam so logs become usable.
4. R-01, R-05, and R-06: make browser and persistent-process recovery authoritative.
5. S-01: fix Windows snapshot path handling because failed restore/discard can threaten user work.
6. E-05 and E-08: make etymon-web the single Vercel root and clear the static public output override.
7. E-06: replace next lint with direct ESLint.
8. E-07: align MicroCheck content placement with lesson rendering.
9. M-05, M-11, and M-12: validate message/tool-call structures early and preserve actionable causes.
10. S-02 through S-06 and the remaining low-frequency tool argument/path issues.

- E-01 is proven from live behavior and code-level diagnosis.
