# Directory continuity candidate

ChatGPT, 2026-09-28, Toronto.

This is a headless Windows experiment, not the production desktop or process driver. Source lives in `packages/core/native/kilocode/directory-continuity-fixture.cpp`; `packages/core/test/kilocode/directory-continuity-experiment.test.ts` checks its actual native results.

The candidate opens directories with directory-read access, shares reads and writes, and excludes delete sharing. Retained child witnesses keep the leaf nonempty. Unlike the rejected no-write-share design, this permits ordinary child and sibling rename, delete and creation. Four directory rename cases refuse; preopened delete access refuses. Preopened write-attributes access remains possible, but the nonempty leaf refuses junction installation. Removing the witness makes that same installation succeed as a positive control. Witness rename and delete refuse.

Actual MSVC `/std:c++20 /EHsc /W4 /WX` compilation and a separately compiled temporary helper produced 20 passing native cases and 24 Bun assertions. To run the check, compile the fixture to a private temporary executable, set `RAYA_DIRECTORY_EXPERIMENT` to its absolute path, then run `bun test test/kilocode/directory-continuity-experiment.test.ts` from `packages/core`. The test intentionally skips without that explicit executable. The fixture is not included in production packaging and requires no desktop capture or input.

Still unproven: races while acquiring the directory chain, volume namespace changes, full process launch/admission, Job lifetime, interruption and restart. A retained witness is not yet proof of an uninterrupted production fence. Do not integrate or mark the installed-host directory gate verified until these pass.

## POSIX and extended reparse probes

ChatGPT, 2026-09-28 06:24 EDT (Toronto).

The private temporary fixture now runs 37 actual native cases. MSVC `/std:c++20 /EHsc /O2 /Z7 /W4 /WX` compilation passed. The focused Bun test passed: 1 test, 41 assertions; fixture execution was approximately 130 ms and the test process completed in 1.09 seconds. No production helper, receipt format, process-launch contract, desktop control, capture, or activation changed. The separately compiled fixture remains excluded from packaging.

- Actual `NtSetInformationFile` POSIX file replacement and unlink controls succeeded while their parent directory was pinned. Source and target names disappeared as expected. The old replaced target remained readable through its previously opened read handle. These controls prove that the fixture exercised supported POSIX behavior rather than treating an unsupported call as protection.
- Fresh DELETE acquisition for pinned cwd and retained witness rename/unlink attempts refused with sharing violation 32. Those attempts stopped at handle acquisition; they did not execute the subsequent set-information call. This is the measured barrier for those cases.
- POSIX replacement calls from independently opened source handles against the retained witness and an empty pinned directory refused with error 32. Reopening each target name confirmed its volume/file identity still matched the retained handle. The protected cwd identity also remained unchanged.
- `FSCTL_SET_REPARSE_POINT_EX` used the same already-open FILE_WRITE_ATTRIBUTES handle as the ordinary reparse experiment. Witness-protected cwd and nonempty ancestor operations refused with directory-not-empty error 145. After the witness was removed, that same extended operation successfully installed and removed a junction. The positive control checks both the packet layout and the access path.

The POSIX probes use [FileDispositionInformationEx](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntddk/ns-ntddk-_file_disposition_information_ex) and [FileRenameInformationEx](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fscc/4217551b-d2c0-42cb-9dc1-69a716cf6d0c), with [native information classes 64 and 65](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/ne-wdm-_file_information_class). Extended reparse packets follow [REPARSE_DATA_BUFFER_EX](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/ns-ntifs-_reparse_data_buffer_ex); their embedded packet offset is statically checked at 32 bytes. Microsoft documents the nonempty-directory refusal for [FSCTL_SET_REPARSE_POINT_EX](https://learn.microsoft.com/en-us/windows-hardware/drivers/ifs/fsctl-set-reparse-point-ex).

This evidence covers fixed disposable directories after their handles and witness were acquired. Acquisition still uses absolute CreateFile paths: it does not prove safe handle-relative acquisition under substitution, witness creation into a concurrently redirected leaf, DOS/volume namespace continuity, prolonged use, suspended process admission, descendant containment, controller/helper loss, or restart. POSIX protected-directory replacement was tested against a retained target; an unpinned directory-replacement baseline was not measured. The next concrete action is a separate bounded handle-relative acquisition fixture that races ancestor substitution and metadata reparse attempts while proving no witness can be created outside the authorized physical directory. Production integration remains gated on that evidence and the Job/recovery matrix.
